# 排哨 CP-SAT 模型｜第一階段工程紀錄

## 核心定位

這是 GitHub 中獨立的 Python OR-Tools 原生 CP-SAT 模型。只使用虛構人員與勤務，不處理軍中真實資料；尚未接到 v7.0 手機網站，也不是 iPhone WASM 求解器。

重要：即使本模型回傳 OPTIMAL，也僅代表「目前已建模限制下的最大填班數」得到了證明，不代表所有勤務規範、跨月補償與公平目標都已完成。

## 從 v7.0 HTML 源碼對照的時段

- 大門 12 班：22–24、00–02、02–04、04–06、06–08、08–10、10–12、12–14、14–16、16–18、18–20、20–22，每班 2 小時。
- 安官 7 班：22–24、00–02、02–04、04–06、06–12、12–18、18–22；勤務時數分別 2、2、2、2、6、6、4 小時。
- 2026 年 11 月共 570 班（大門 360、安官 210）。
- 2026 年 12 月共 589 班（大門 372、安官 217）。

## 已寫入模型的強制限制

1. 每班最多一人；缺班可保持空白，不以虛構人員冒充。
2. 安官同日最多一班；大門同日最多 3 班且滿足每班之間 6 小時休息。
3. 站一歇一：當天任一班，隔天整天不能再排。
4. 同班號時段 1～2 天內不得重複；支援輸入已知跨月歷史。
5. 連續星期日留守禁排；大門週日 06–20、安官週日 18–22。
6. 休假及收假日、假前夜哨、受訓、值星、督伙前後休息、夜查三日、車勤、免哨、伙房等候選排除。
7. 人工固定班次與空缺不得被求解器擅自改寫；無效固定班次直接拒絕。
8. 求解結果另用獨立 Python 程式檢查硬限制；沒有求解結果時不宣稱成功。

## 測試方式與證據分層

官方 OR-Tools Python 套件由 GitHub Actions 原生 runner 安裝。native-cpsat 工作執行：
python -m unittest discover -s tests -p 'test_roster_cp_sat.py' -v

不同的成功必須分開報告：
- 規格數量正確：只證明班表時段產生正確。
- 原生 CP-SAT 小型虛構案例 OPTIMAL：只證明所測小型部分模型。
- 589 班純虛構無額外禁排的證明樣本：只證明這種簡化情況的可行性，不能推論實際人力足夠。
- 真正 OR-Tools CP-SAT WASM：需 Node 真實執行、獨立數值核對。
- iPhone CP-SAT WASM：需使用者手機在 HTML Viewer 真實執行。
- 正式整月排哨：需完整規則、資料驗證、獨立審查及核定。
